61. Rotate List

⚠️ Edge Cases
Empty List (head == null), Single Node, Zero Rotations (k == 0).
🌍 Real-World Applications
Circular buffers in embedded systems, rotating banner ads, round-robin scheduling algorithms.
🐢 The Brute Force Approach
Move the last node to the front of the list, and run this operation $k$ times in a loop. Fails because $O(N)$ traversal $k$ times results in $O(N \times k)$ Time Limit Exceeded.
// Brute Force: rotate one step at a time, k times
class Solution {
    public ListNode rotateRight(ListNode head, int k) {
        if (head == null || head.next == null) return head;

        for (int step = 0; step < k; step++) {
            // Find the second-to-last node
            ListNode prev = head;
            while (prev.next.next != null) {
                prev = prev.next;
            }
            ListNode last = prev.next;
            prev.next = null;
            last.next = head;
            head = last;
        }
        return head;
    }
}
// Time: O(N * k)  — TLE when k is huge
// Space: O(1)
🧩 Pattern
Find Length & Make Circular (Two Pointers/Traversal).
🚀 The Optimal Strategy
1. Get Length.
2. k = k % length.
3. Connect tail to head to make a circle.
4. Walk length - k - 1 steps from head to find new tail. Set next to null.
☕ The Java Code Optimal
class Solution {
    public ListNode rotateRight(ListNode head, int k) {
        if(head == null || head.next == null || k == 0) return head;

        ListNode oldTail = head;
        int length = 1;
        while(oldTail.next != null) {
            oldTail = oldTail.next;
            length++;
        }

        k = k % length;
        if(k == 0) return head;
        
        oldTail.next = head;

        ListNode newTail = head;
        for(int i = 0; i < length - k - 1; i++) {
            newTail = newTail.next;
        }

        ListNode newHead = newTail.next; 
        newTail.next = null;

        return newHead;
    }
}
📊 Complexity
Time: O(N)
Space: O(1)

24. Swap Nodes in Pairs

⚠️ Edge Cases
Empty List, Single Node, Odd Number of Nodes.
🌍 Real-World Applications
Cryptographic Algorithms (data permutation), Network Packet Processing (endianness flipping).
🐢 The Brute Force Approach
Iterate and swap the integer values inside the nodes. Inefficient for real-world nodes with massive data payloads.
// Brute Force: swap values only, don't touch pointers
class Solution {
    public ListNode swapPairs(ListNode head) {
        ListNode curr = head;
        while (curr != null && curr.next != null) {
            int tmp = curr.val;
            curr.val = curr.next.val;
            curr.next.val = tmp;
            curr = curr.next.next;
        }
        return head;
    }
}
// Time: O(N), Space: O(1)
// Rejected in interviews: many problems specify "you may not modify the
// values in the list's nodes — only nodes themselves may be changed."
🧩 Pattern
Dummy Node + Pointer Rewiring
🚀 The Optimal Strategy
Attach a Dummy Node. Use a prev pointer. Rewire: prev.next = second, first.next = second.next, second.next = first. Move prev = first.
☕ The Java Code Optimal
class Solution {
    public ListNode swapPairs(ListNode head) {
        ListNode dummy = new ListNode(0);
        dummy.next = head;
        ListNode prev = dummy;
        
        while (prev.next != null && prev.next.next != null) {
            ListNode first = prev.next;
            ListNode second = prev.next.next;
            
            prev.next = second;
            first.next = second.next;
            second.next = first;
            
            prev = first; 
        }
        return dummy.next;
    }
}
📊 Complexity
Time: O(N)
Space: O(1)

735. Asteroid Collision

⚠️ Edge Cases
No Collisions ([-5, 5]), The Bowling Ball ([1, 2, 3, -100]), Mutually Assured Destruction.
🌍 Real-World Applications
Physics Engines / Game Dev, Financial Order Books (matching engine mechanics).
🐢 The Brute Force Approach
Scan array, resolve collision, delete loser, shift elements. O(N²) time complexity.
// Brute Force: use an ArrayList and re-scan after every collision
class Solution {
    public int[] asteroidCollision(int[] asteroids) {
        List<Integer> list = new ArrayList<>();
        for (int a : asteroids) list.add(a);

        boolean changed = true;
        while (changed) {
            changed = false;
            for (int i = 0; i < list.size() - 1; i++) {
                int left = list.get(i), right = list.get(i + 1);
                if (left > 0 && right < 0) {
                    if (Math.abs(left) > Math.abs(right)) {
                        list.remove(i + 1);
                    } else if (Math.abs(left) < Math.abs(right)) {
                        list.remove(i);
                    } else {
                        list.remove(i + 1);
                        list.remove(i);
                    }
                    changed = true;
                    break; // restart scan
                }
            }
        }
        return list.stream().mapToInt(Integer::intValue).toArray();
    }
}
// Time: O(N^2) — every collision triggers a full re-scan + shift
// Space: O(N)
🧩 Pattern
The Stack (LIFO)
🚀 The Optimal Strategy
Use a Stack for survivors. Collision ONLY happens if stack top is Right (+) and current is Left (-). Use a while loop to let negative asteroids smash through the stack. Use Math.abs() for size comparison.
☕ The Java Code Optimal
class Solution {
    public int[] asteroidCollision(int[] asteroids) {
        Stack stack = new Stack<>();
        for (int ast : asteroids) {
            boolean destroyed = false;
            while (!stack.isEmpty() && ast < 0 && stack.peek() > 0) {
                if (stack.peek() < Math.abs(ast)) {
                    stack.pop();
                    continue; 
                } else if (stack.peek() == Math.abs(ast)) {
                    stack.pop();
                }
                destroyed = true;
                break;
            }
            if (!destroyed) stack.push(ast);
        }
        int[] result = new int[stack.size()];
        for (int i = result.length - 1; i >= 0; i--) result[i] = stack.pop();
        return result;
    }
}
📊 Complexity
Time: O(N)
Space: O(N)

20. Valid Parentheses

⚠️ Edge Cases
Odd Length String (instantly false), Starts with a Closing Bracket.
🌍 Real-World Applications
Compilers and Interpreters (syntax parsing), JSON Validation.
🐢 The Brute Force Approach
Continuously use .replace("()", ""). Fails because strings are immutable in Java.
// Brute Force: repeatedly strip out matched adjacent pairs
class Solution {
    public boolean isValid(String s) {
        int prevLen;
        do {
            prevLen = s.length();
            s = s.replace("()", "").replace("[]", "").replace("{}", "");
        } while (s.length() != prevLen);
        return s.isEmpty();
    }
}
// Time: O(N^2) — each .replace() is O(N) and rebuilds the whole string,
//              and we may need up to N/2 passes
// Space: O(N) — new string allocated on every replace call
🧩 Pattern
The Stack (LIFO) + HashMap Mapping
🚀 The Optimal Strategy
Map closing brackets to opening pairs. If opening, push to stack. If closing, pop the stack and check if it matches map value.
☕ The Java Code Optimal
class Solution {
    public boolean isValid(String s) {
        if (s.length() % 2 != 0) return false;
        Stack stack = new Stack<>();
        Map myMap = new HashMap<>();
        myMap.put(')', '(');
        myMap.put(']', '[');
        myMap.put('}', '{');

        for (char c : s.toCharArray()) {
            if (myMap.containsKey(c)) {
                if (stack.isEmpty() || stack.pop() != myMap.get(c)) return false;
            } else {
                stack.push(c);
            }
        }
        return stack.isEmpty();
    }
}
📊 Complexity
Time: O(N)
Space: O(N)

503. Next Greater Element II

⚠️ Edge Cases
Strictly Decreasing Array (needs wrap-around), All Identical Elements.
🌍 Real-World Applications
Stock Market algorithms (next price surge), Circular Server Resource Allocation.
🐢 The Brute Force Approach
Nested for loops to scan forward, wrapping back to index 0 manually. Results in O(N²) TLE.
// Brute Force: for each index, scan up to N positions forward with wrap-around
class Solution {
    public int[] nextGreaterElements(int[] nums) {
        int n = nums.length;
        int[] result = new int[n];
        Arrays.fill(result, -1);

        for (int i = 0; i < n; i++) {
            for (int j = 1; j < n; j++) {
                int next = nums[(i + j) % n]; // wrap
                if (next > nums[i]) {
                    result[i] = next;
                    break;
                }
            }
        }
        return result;
    }
}
// Time: O(N^2), Space: O(1) extra (output array not counted)
🧩 Pattern
Monotonic Decreasing Stack + Circular Array Traversal (%)
🚀 The Optimal Strategy
Use a stack to store indices of unresolved numbers. Loop up to 2 * n. Use i % n to safely wrap around. While current number is greater than the value at stack.peek(), pop the stack and record.
☕ The Java Code Optimal
class Solution {
    public int[] nextGreaterElements(int[] nums) {
        Deque stack = new ArrayDeque<>();
        int n = nums.length;
        int[] result = new int[n];
        Arrays.fill(result, -1);

        for(int i = 0; i < 2 * n; i++) {
            int current = nums[i % n];
            while(!stack.isEmpty() && current > nums[stack.peek()]) {
                result[stack.pop()] = current;
            }
            if(i < n) stack.push(i);
        }   
        return result;
    }
}
📊 Complexity
Time: O(N)
Space: O(N)

94. Binary Tree Inorder Traversal

⚠️ Edge Cases
Empty Tree (root == null), Degenerate straight-line tree.
🌍 Real-World Applications
Binary Search Trees (returns perfectly sorted ascending data), Math Expression Trees.
🐢 The Brute Force Approach
Standard recursion. Can fail with a StackOverflowError if the tree is massively unbalanced.
// Brute Force: recursive inorder traversal
class Solution {
    public List<Integer> inorderTraversal(TreeNode root) {
        List<Integer> result = new ArrayList<>();
        helper(root, result);
        return result;
    }

    private void helper(TreeNode node, List<Integer> result) {
        if (node == null) return;
        helper(node.left, result);   // left
        result.add(node.val);        // root
        helper(node.right, result);  // right
    }
}
// Time: O(N), Space: O(H) call stack
// Correct, but a degenerate skewed tree (H ≈ N) can blow the JVM stack.
// Iterative version below uses an explicit stack so depth is bounded by heap.
🧩 Pattern
Depth-First Search (DFS) + Explicit Iterative Stack
🚀 The Optimal Strategy
Mimic system call stack manually. Dive to bottom-left, pushing nodes to stack. When hitting null, pop, process value, shift pointer to right child.
☕ The Java Code Optimal
class Solution {
    public List<Integer> inorderTraversal(TreeNode root) {
        List result = new ArrayList<>();
        Stack stack = new Stack<>();
        TreeNode current = root;
        
        while (current != null || !stack.isEmpty()) {
            while (current != null) {
                stack.push(current);
                current = current.left;
            }
            current = stack.pop();
            result.add(current.val);
            current = current.right;
        }
        return result;
    }
}
📊 Complexity
Time: O(N)
Space: O(H) where H is tree height.

100. Same Tree

⚠️ Edge Cases
Both Trees are Empty, Only One Tree is Empty, Same Values but Different Structure.
🌍 Real-World Applications
React Virtual DOM comparison, File System Comparisons, Compiler Abstract Syntax Trees (AST).
🐢 The Brute Force Approach
Run an Inorder traversal on both trees and store values in Arrays. Compare arrays. Wastes memory and time.
// Brute Force: serialize both trees, compare the serializations
class Solution {
    public boolean isSameTree(TreeNode p, TreeNode q) {
        List<Integer> a = new ArrayList<>();
        List<Integer> b = new ArrayList<>();
        serialize(p, a);
        serialize(q, b);
        return a.equals(b);
    }

    private void serialize(TreeNode node, List<Integer> out) {
        if (node == null) {
            out.add(null); // null markers are REQUIRED to preserve structure
            return;
        }
        out.add(node.val);
        serialize(node.left, out);
        serialize(node.right, out);
    }
}
// Time: O(N), Space: O(N) for the two lists
// Works, but allocates 2N memory and always walks the full tree — even when
// a mismatch at the root could let us short-circuit immediately.
🧩 Pattern
Synchronous Depth-First Search (DFS) / Recursion
🚀 The Optimal Strategy
Stand on the root of both trees simultaneously. Ask 3 questions: 1. Both null? (Match!) 2. One null? (Mismatch!) 3. Values different? (Mismatch!). If all pass, recursively check left and right children.
☕ The Java Code Optimal
class Solution {
    public boolean isSameTree(TreeNode p, TreeNode q) {
        if (p == null && q == null) return true;
        if (p == null || q == null) return false;
        if (p.val != q.val) return false;
        
        return isSameTree(p.left, q.left) && isSameTree(p.right, q.right);
    }
}
📊 Complexity
Time: O(N) where N is smaller tree size.
Space: O(H) recursion stack.

144. Binary Tree Preorder Traversal

⚠️ Edge Cases
Empty Tree (root == null), Single Node, Left-skewed or Right-skewed degenerate tree.
🌍 Real-World Applications
Serializing/cloning trees (root-first order lets you rebuild structure on the way down), printing directory hierarchies, expression tree evaluation in prefix (Polish) notation.
🐢 The Brute Force Approach
Standard recursion. Correct and clean, but a deeply skewed tree can blow the JVM call stack.
// Brute Force: recursive preorder — root, left, right
class Solution {
    public List<Integer> preorderTraversal(TreeNode root) {
        List<Integer> result = new ArrayList<>();
        helper(root, result);
        return result;
    }

    private void helper(TreeNode node, List<Integer> result) {
        if (node == null) return;
        result.add(node.val);         // root
        helper(node.left, result);    // left
        helper(node.right, result);   // right
    }
}
// Time: O(N), Space: O(H) call stack
// Works, but the iterative version uses heap memory for the stack,
// which survives much deeper trees than the JVM call stack can.
🧩 Pattern
DFS + Explicit Stack (Push Right Before Left)
🚀 The Optimal Strategy
Push root onto a stack. Loop: pop a node, record its value, then push its right child first, then its left. Because stack is LIFO, left comes out next — giving preorder (root → left → right).
☕ The Java Code Optimal
class Solution {
    public List<Integer> preorderTraversal(TreeNode root) {
        List<Integer> result = new ArrayList<>();
        if (root == null) return result;

        Deque<TreeNode> stack = new ArrayDeque<>();
        stack.push(root);

        while (!stack.isEmpty()) {
            TreeNode node = stack.pop();
            result.add(node.val);              // visit root

            // Push right FIRST so left is processed next (LIFO)
            if (node.right != null) stack.push(node.right);
            if (node.left != null)  stack.push(node.left);
        }
        return result;
    }
}
📊 Complexity
Time: O(N)
Space: O(H) where H is tree height (worst case O(N) for a skewed tree).

145. Binary Tree Postorder Traversal

⚠️ Edge Cases
Empty Tree, Single Node, Fully left-skewed tree (all children are left children).
🌍 Real-World Applications
Safely deleting trees bottom-up (free children before parent — kernel memory management does this), evaluating expression trees (compute operands before operator), calculating directory sizes (children's sizes must be known before parent).
🐢 The Brute Force Approach
Standard recursion — "left, right, root" ordering. Clean, but same call stack risk as the other traversals on degenerate trees.
// Brute Force: recursive postorder — left, right, root
class Solution {
    public List<Integer> postorderTraversal(TreeNode root) {
        List<Integer> result = new ArrayList<>();
        helper(root, result);
        return result;
    }

    private void helper(TreeNode node, List<Integer> result) {
        if (node == null) return;
        helper(node.left, result);    // left
        helper(node.right, result);   // right
        result.add(node.val);         // root (visited LAST)
    }
}
// Time: O(N), Space: O(H) call stack
🧩 Pattern
Reverse-Preorder Trick (Root-Right-Left, then reverse)
🚀 The Optimal Strategy
True iterative postorder is tricky because you need to visit a node after both its children. The clever hack: do a modified preorder where you push left first, right second — this gives "root, right, left" order. Then reverse the result list to get "left, right, root" — which is postorder.
☕ The Java Code Optimal
class Solution {
    public List<Integer> postorderTraversal(TreeNode root) {
        LinkedList<Integer> result = new LinkedList<>();
        if (root == null) return result;

        Deque<TreeNode> stack = new ArrayDeque<>();
        stack.push(root);

        while (!stack.isEmpty()) {
            TreeNode node = stack.pop();
            result.addFirst(node.val); // prepend — reverses the traversal

            // Push left FIRST so right is processed next (LIFO)
            if (node.left != null)  stack.push(node.left);
            if (node.right != null) stack.push(node.right);
        }
        return result;
    }
}
// addFirst on LinkedList is O(1), so we get reversal "for free"
// without a separate Collections.reverse() pass.
📊 Complexity
Time: O(N)
Space: O(H) for the stack, O(N) for the result list.

496. Next Greater Element I

⚠️ Edge Cases
Empty arrays, elements in strictly descending order (no greater element exists).
🌍 Real-World Applications
Financial market stop-loss triggers, querying related data streams where one determines the limits of another.
🐢 The Brute Force Approach
For every element in nums1, find it in nums2, then scan right to find the next greater element. O(N * M) time complexity.
// Brute Force: for each query, linear scan nums2
class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {
        int[] res = new int[nums1.length];
        for (int i = 0; i < nums1.length; i++) {
            res[i] = -1;
            int j = 0;
            // 1) locate nums1[i] inside nums2
            while (j < nums2.length && nums2[j] != nums1[i]) j++;
            // 2) scan forward for the first greater value
            for (int k = j + 1; k < nums2.length; k++) {
                if (nums2[k] > nums1[i]) {
                    res[i] = nums2[k];
                    break;
                }
            }
        }
        return res;
    }
}
// Time: O(N * M), Space: O(1) extra
🧩 Pattern
Monotonic Decreasing Stack + HashMap
🚀 The Optimal Strategy
Iterate through nums2. Keep a monotonic decreasing stack of values. If current value > stack top, pop stack and map popped value -> current value. Finally, loop through nums1 and fetch answers from the map.
☕ The Java Code Optimal
class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {
        Map nextGreater = new HashMap<>();
        Stack stack = new Stack<>();
        
        for (int num : nums2) {
            while (!stack.isEmpty() && num > stack.peek()) {
                nextGreater.put(stack.pop(), num);
            }
            stack.push(num);
        }
        
        int[] res = new int[nums1.length];
        for (int i = 0; i < nums1.length; i++) {
            res[i] = nextGreater.getOrDefault(nums1[i], -1);
        }
        return res;
    }
}
📊 Complexity
Time: O(N + M)
Space: O(N) for map and stack.

739. Daily Temperatures

⚠️ Edge Cases
Temperatures strictly decreasing (all answers 0).
🌍 Real-World Applications
Weather forecasting dashboards, financial stock waiting periods.
🐢 The Brute Force Approach
For each day, scan the rest of the array forward to find a warmer day. O(N²) time complexity.
// Brute Force: nested loop — for each day, look ahead until warmer
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] result = new int[n];
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (temperatures[j] > temperatures[i]) {
                    result[i] = j - i;
                    break;
                }
            }
        }
        return result;
    }
}
// Time: O(N^2) — TLE on LeetCode (N up to 10^5)
// Space: O(1) extra
🧩 Pattern
Monotonic Decreasing Stack (Storing Indices)
🚀 The Optimal Strategy
Iterate through array. Store indices in stack. If current temp > temp at stack top, pop the index. Calculate difference (current index - popped index) and store in result array.
☕ The Java Code Optimal
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int[] result = new int[temperatures.length];
        Stack stack = new Stack<>(); // Stores indices
        
        for (int i = 0; i < temperatures.length; i++) {
            while (!stack.isEmpty() && temperatures[i] > temperatures[stack.peek()]) {
                int prevIndex = stack.pop();
                result[prevIndex] = i - prevIndex;
            }
            stack.push(i);
        }
        return result;
    }
}
📊 Complexity
Time: O(N)
Space: O(N) for the stack.

84. Largest Rectangle in Histogram

⚠️ Edge Cases
All bars same height, strictly increasing or strictly decreasing histograms.
🌍 Real-World Applications
UI layout engines rendering bounding boxes, skyline silhouette calculations.
🐢 The Brute Force Approach
Expand left and right from every single bar until hitting a shorter bar. O(N²) time complexity.
// Brute Force: for each bar, expand outwards to find its max rectangle
class Solution {
    public int largestRectangleArea(int[] heights) {
        int n = heights.length;
        int maxArea = 0;
        for (int i = 0; i < n; i++) {
            int h = heights[i];
            int left = i, right = i;
            while (left - 1 >= 0 && heights[left - 1] >= h) left--;
            while (right + 1 < n && heights[right + 1] >= h) right++;
            maxArea = Math.max(maxArea, h * (right - left + 1));
        }
        return maxArea;
    }
}
// Time: O(N^2) — TLE when N is large
// Space: O(1) extra
// Intuition: this does the right thing but re-walks the same bars over and
// over. The monotonic stack version computes the same "left/right boundary"
// in a single amortized O(N) pass.
🧩 Pattern
Monotonic Increasing Stack (Index, Height)
🚀 The Optimal Strategy
Maintain a stack of increasing heights. When a shorter bar appears, it acts as a boundary. Pop the taller bars, calculating their area: `height * (current index - popped index)`. Push the new bar but borrow the popped index.
☕ The Java Code Optimal
class Solution {
    public int largestRectangleArea(int[] heights) {
        Stack stack = new Stack<>(); // [index, height]
        int maxArea = 0;
        
        for (int i = 0; i < heights.length; i++) {
            int start = i;
            while (!stack.isEmpty() && stack.peek()[1] > heights[i]) {
                int[] popped = stack.pop();
                maxArea = Math.max(maxArea, popped[1] * (i - popped[0]));
                start = popped[0]; // Borrow the index!
            }
            stack.push(new int[]{start, heights[i]});
        }
        
        // Resolve remaining bars in stack
        for (int[] element : stack) {
            maxArea = Math.max(maxArea, element[1] * (heights.length - element[0]));
        }
        return maxArea;
    }
}
📊 Complexity
Time: O(N)
Space: O(N)

203. Remove Linked List Elements

⚠️ Edge Cases
List is empty, all elements in list match the target value.
🌍 Real-World Applications
Filtering data streams, sanitizing active connection linked lists in networking.
🐢 The Brute Force Approach
Try to handle the head separately using special if-statements, then loop. Leads to messy code and missed edge cases.
// Brute Force: handle head separately, then handle the rest
class Solution {
    public ListNode removeElements(ListNode head, int val) {
        // Step 1: strip off matching nodes from the front
        while (head != null && head.val == val) {
            head = head.next;
        }
        // Step 2: handle the interior
        ListNode curr = head;
        while (curr != null && curr.next != null) {
            if (curr.next.val == val) {
                curr.next = curr.next.next;
            } else {
                curr = curr.next;
            }
        }
        return head;
    }
}
// Time: O(N), Space: O(1)
// Correct, but splits the logic into two loops. Easy to mis-handle edge
// cases like all-matching lists. The dummy-node version unifies both paths.
🧩 Pattern
Dummy Node Pattern
🚀 The Optimal Strategy
Create a dummy node pointing to head. Traverse using a `curr` pointer starting at dummy. If `curr.next.val == target`, skip it (`curr.next = curr.next.next`). Otherwise, move `curr` forward.
☕ The Java Code Optimal
class Solution {
    public ListNode removeElements(ListNode head, int val) {
        ListNode dummy = new ListNode(-1);
        dummy.next = head;
        ListNode curr = dummy;
        
        while (curr.next != null) {
            if (curr.next.val == val) {
                curr.next = curr.next.next; // Skip node
            } else {
                curr = curr.next; // Move forward
            }
        }
        return dummy.next;
    }
}
📊 Complexity
Time: O(N)
Space: O(1)

3217. Delete Nodes From Linked List Present in Array

⚠️ Edge Cases
Array has millions of elements, all nodes in list get deleted.
🌍 Real-World Applications
Database bulk row deletion (e.g. DELETE FROM table WHERE id IN (list)).
🐢 The Brute Force Approach
For every node, iterate through the entire array to check if the value exists. O(N * M) time.
// Brute Force: linear-scan the array for every linked list node
class Solution {
    public ListNode modifiedList(int[] nums, ListNode head) {
        ListNode dummy = new ListNode(0);
        dummy.next = head;
        ListNode curr = dummy;

        while (curr.next != null) {
            if (contains(nums, curr.next.val)) {
                curr.next = curr.next.next;
            } else {
                curr = curr.next;
            }
        }
        return dummy.next;
    }

    private boolean contains(int[] nums, int target) {
        for (int n : nums) if (n == target) return true;
        return false;
    }
}
// Time: O(N * M), Space: O(1) extra
// The HashSet version turns the inner O(M) scan into O(1) lookup.

HashSet Lookup + Dummy Node
🚀 The Optimal Strategy
First, convert the array into a HashSet for O(1) lookups. Then use the standard Dummy Node pattern to traverse and delete nodes that exist in the set.

21. Merge Two Sorted Lists

⚠️ Edge Cases
One list is empty, both lists are empty.
🌍 Real-World Applications
Merge sort subroutine, combining chronologically sorted log files.
🐢 The Brute Force Approach
Dump all nodes into an array, sort the array, and build a brand new linked list. O((N+M) log(N+M)) time.
// Brute Force: collect all values, sort, rebuild a new list
class Solution {
    public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
        List<Integer> values = new ArrayList<>();
        while (list1 != null) { values.add(list1.val); list1 = list1.next; }
        while (list2 != null) { values.add(list2.val); list2 = list2.next; }

        Collections.sort(values);

        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;
        for (int v : values) {
            tail.next = new ListNode(v);
            tail = tail.next;
        }
        return dummy.next;
    }
}
// Time: O((N+M) log(N+M)), Space: O(N+M)
// Throws away the fact that both inputs are already sorted — classic sign
// there's a faster merge-based solution that just walks both lists in parallel.
🧩 Pattern
Dummy Node + Two Pointers
🚀 The Optimal Strategy
Use a dummy node to anchor the result. Use a `tail` pointer. Compare `list1.val` and `list2.val`, attach the smaller one to `tail.next`, and advance that list's pointer. Finally, attach any remaining nodes from the non-empty list.
☕ The Java Code Optimal
class Solution {
    public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;
        
        while (list1 != null && list2 != null) {
            if (list1.val < list2.val) {
                tail.next = list1;
                list1 = list1.next;
            } else {
                tail.next = list2;
                list2 = list2.next;
            }
            tail = tail.next;
        }
        
        // Attach remainder
        if (list1 != null) tail.next = list1;
        if (list2 != null) tail.next = list2;
        
        return dummy.next;
    }
}
📊 Complexity
Time: O(N + M)
Space: O(1) in-place merging

682. Baseball Game

⚠️ Edge Cases
Empty operations list, negative numbers, multiple consecutive invalidations.
🌍 Real-World Applications
Custom rule calculation engines, implementing 'Undo' functionality in text editors.
🐢 The Brute Force Approach
Use an array with manual index manipulation to keep track of the end of the list. Prone to off-by-one errors.
// Brute Force: fixed-size array with a manually-tracked "size" pointer
class Solution {
    public int calPoints(String[] operations) {
        int[] scores = new int[operations.length];
        int size = 0;

        for (String op : operations) {
            if (op.equals("C")) {
                size--; // invalidate previous
            } else if (op.equals("D")) {
                scores[size] = 2 * scores[size - 1];
                size++;
            } else if (op.equals("+")) {
                scores[size] = scores[size - 1] + scores[size - 2];
                size++;
            } else {
                scores[size++] = Integer.parseInt(op);
            }
        }

        int sum = 0;
        for (int i = 0; i < size; i++) sum += scores[i];
        return sum;
    }
}
// Time: O(N), Space: O(N)
// Same complexity as the stack version — but juggling `size` manually is
// easy to get wrong. Stack abstracts that away (push/pop/peek read naturally).
🧩 Pattern
The Stack
🚀 The Optimal Strategy
Iterate over operations. Use a Stack. 'C' -> pop. 'D' -> peek and push double. '+' -> pop top, peek new top, calculate sum, push both back plus the sum. Otherwise -> parse integer and push.
☕ The Java Code Optimal
class Solution {
    public int calPoints(String[] operations) {
        Stack stack = new Stack<>();
        
        for (String op : operations) {
            if (op.equals("+")) {
                int top1 = stack.pop();
                int top2 = stack.peek();
                stack.push(top1);
                stack.push(top1 + top2);
            } else if (op.equals("D")) {
                stack.push(2 * stack.peek());
            } else if (op.equals("C")) {
                stack.pop();
            } else {
                stack.push(Integer.parseInt(op));
            }
        }
        
        int sum = 0;
        for (int score : stack) {
            sum += score;
        }
        return sum;
    }
}
📊 Complexity
Time: O(N)
Space: O(N)

101. Symmetric Tree

⚠️ Edge Cases
Empty Tree (trivially symmetric), Single Node, Asymmetric shape even when values match (e.g. [1,2,2,null,3,null,3] — values look fine but structure is mirrored wrong).
🌍 Real-World Applications
Detecting palindromic data structures, validating UI layout symmetry, image mirror-symmetry detection, chemistry molecule symmetry checks.
🐢 The Brute Force Approach
Serialize the left subtree left-to-right and the right subtree right-to-left into two lists, then compare them. Works, but allocates O(N) extra memory and always walks the full tree — even when a mismatch at the top could let us bail out immediately.
// Brute Force: build left-to-right and right-to-left serializations, compare
class Solution {
    public boolean isSymmetric(TreeNode root) {
        if (root == null) return true;
        List<Integer> leftOrder  = new ArrayList<>();
        List<Integer> rightOrder = new ArrayList<>();
        dfsLeft(root.left, leftOrder);
        dfsRight(root.right, rightOrder);
        return leftOrder.equals(rightOrder);
    }

    // Normal preorder: root, left, right
    private void dfsLeft(TreeNode node, List<Integer> out) {
        if (node == null) { out.add(null); return; }
        out.add(node.val);
        dfsLeft(node.left, out);
        dfsLeft(node.right, out);
    }

    // Mirrored preorder: root, right, left
    private void dfsRight(TreeNode node, List<Integer> out) {
        if (node == null) { out.add(null); return; }
        out.add(node.val);
        dfsRight(node.right, out);
        dfsRight(node.left, out);
    }
}
// Time: O(N), Space: O(N) for the two lists
// Null markers are REQUIRED — without them, [1,2] and [1,null,2] look the same.
🧩 Pattern
Mirrored DFS / Two-Pointer Recursion — same skeleton as Same Tree (LC 100), but pair the children CROSSED: left ↔ right instead of left ↔ left.
🚀 The Optimal Strategy
Compare the left and right subtrees as mirror images using two pointers p and q. At each step ask 3 questions: 1. Both null? (Mirror match!) 2. Exactly one null? (Mismatch!) 3. Values differ? (Mismatch!). If all pass, recurse on the outer pair (p.left vs q.right) AND the inner pair (p.right vs q.left). Both must match.
☕ The Java Code Optimal
class Solution {
    public boolean isSymmetric(TreeNode root) {
        if (root == null) return true;
        return checkSubTrees(root.left, root.right);
    }

    private boolean checkSubTrees(TreeNode p, TreeNode q) {
        // Case 1: both null -> mirror match
        if (p == null && q == null) return true;

        // Case 2: exactly one null -> structural mismatch
        if (p == null || q == null) return false;

        // Case 3: values must match AND mirror children must match
        return p.val == q.val
            && checkSubTrees(p.left,  q.right)   // outer pair
            && checkSubTrees(p.right, q.left);   // inner pair
    }
}
// Key insight: this is LC 100 (Same Tree) with the child pairing CROSSED.
//   Same Tree:      recurse(p.left, q.left)  AND recurse(p.right, q.right)
//   Symmetric Tree: recurse(p.left, q.right) AND recurse(p.right, q.left)
📊 Complexity
Time: O(N) — visits each node once.
Space: O(H) recursion stack — O(log N) balanced, O(N) worst case for a skewed tree.

226. Invert Binary Tree

⚠️ Edge Cases
Empty Tree (root == null), Single Node (inverting a leaf is a no-op), Already-symmetric tree (inverting produces an equal tree), Deeply skewed tree (recursive version risks StackOverflowError).
🌍 Real-World Applications
Reversing hierarchical UI layouts (e.g. right-to-left language rendering), generating mirror images of expression trees, flipping decision tree evaluations, the classic Homebrew-at-Google interview story that made this problem famous.
🐢 The Brute Force Approach
Serialize the tree into a list, manually build a brand new tree that's the mirror, return the new root. Allocates O(N) extra nodes, throws away the input — wasteful when an in-place swap is possible.
// Brute Force: materialize values, then rebuild a mirrored tree from scratch
class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) return null;

        // Collect nodes in level order
        List<TreeNode> level = new ArrayList<>();
        level.add(root);
        int i = 0;
        while (i < level.size()) {
            TreeNode n = level.get(i++);
            if (n != null) {
                level.add(n.left);
                level.add(n.right);
            }
        }

        // Build a mirror-copy tree (new nodes, swapped children)
        return buildMirror(root);
    }

    private TreeNode buildMirror(TreeNode node) {
        if (node == null) return null;
        TreeNode copy = new TreeNode(node.val);
        copy.left  = buildMirror(node.right); // swap while copying
        copy.right = buildMirror(node.left);
        return copy;
    }
}
// Time: O(N), Space: O(N) for the new tree + O(H) call stack
// Correct, but allocates a full second tree when we could just swap pointers
// inside the existing tree.
🧩 Pattern
Bottom-Up Recursive Mutation — the same "mutate via recursion" template used by LC 114 (Flatten), LC 617 (Merge Trees), and LC 538 (BST to Greater Tree). Recurse on children first, then do work at the current node.
🚀 The Optimal Strategy
At every node ask: "What does it mean to invert the subtree rooted here?" Answer: (1) recursively invert my left and right subtrees, (2) swap them. Return the node. The swap happens bottom-up — deepest nodes swap first, root swaps last, as the call stack unwinds.
☕ The Java Code Optimal
class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) return null;

        // Recurse on both subtrees FIRST
        TreeNode leftInverted  = invertTree(root.left);
        TreeNode rightInverted = invertTree(root.right);

        // Then swap them at the current node
        root.left  = rightInverted;
        root.right = leftInverted;

        return root;
    }
}

// BEFORE overwriting it, otherwise you invert the right subtree twice):
//
// if (root == null) return null;
// TreeNode temp = root.left;

// root.right = invertTree(temp);

🔁 Iterative Alternative (BFS)
When the tree is deeply skewed, the recursive call stack can blow. A queue-based BFS does the same work with heap memory instead.
class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) return null;

        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(root);

        while (!queue.isEmpty()) {
            TreeNode node = queue.poll();

            // Swap children
            TreeNode temp = node.left;
            node.left  = node.right;
            node.right = temp;

            if (node.left  != null) queue.offer(node.left);
            if (node.right != null) queue.offer(node.right);
        }
        return root;
    }
}
// Same O(N) time. Space is O(W) where W = max tree width,
// which is bounded by the heap instead of the JVM stack.
